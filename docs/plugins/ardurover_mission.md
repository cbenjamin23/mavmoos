# ArduRover native missions

`ardurover_control` owns this opt-in workflow for the pinned conventional `rover` and powered `motorboat-skid` SITL profiles. Set `control_mission_execution=true`, enable native actions, load `missions`, and use the same private `auto_recovery_directory` across bridge restarts. Stock helm keeps its ordinary Guided navigation role.

## Vehicle contract and acceptance

The pinned Rover dispatches `MAV_CMD_MISSION_START` to mode 10 with zero first/last arguments. Its shared mission cursor excludes HOME from the reported total. It reports a stopped mission as `NOT_STARTED` and uses `MIS_RESTART=0` to resume the previous cursor on returning to AUTO. Its default mission-end behavior stops within AUTO, while boat Loiter can maintain position within AUTO. A terminal cursor therefore retains authority until explicit handback. [Pinned Rover command handler](https://github.com/ArduPilot/ardupilot/blob/04cf6486e8d42ce138de816e8466244346ed77cb/Rover/GCS_MAVLink_Rover.cpp#L552-L560) · [Pinned AUTO implementation](https://github.com/ArduPilot/ardupilot/blob/04cf6486e8d42ce138de816e8466244346ed77cb/Rover/mode_auto.cpp) · [Shared cursor sender](https://github.com/ArduPilot/ardupilot/blob/04cf6486e8d42ce138de816e8466244346ed77cb/libraries/GCS_MAVLink/GCS_Common.cpp#L694-L734)

- Use disarmed upload and verified readback through the shared `missions` provider. Bind HOME and two to seven zero-altitude waypoints to the current session and bound home. Admission requires explicit arming, a settled Hold (or powered-boat Loiter), a fresh exact-size cursor, and readbacks of the bounded mission settings.
- Start selects waypoint 1 and observes the selected cursor before asking for native AUTO. A matching wire ACK is reported as `ACK_OBSERVED` for diagnostics. The phase advances only after local command handoff and the required fresh mode, cursor and stop observations within its original deadline. A missing, delayed or denied ACK cannot decide the phase.
- Pause requests ground Hold or powered-boat Loiter. Pause requires a fresh mode, stopped cursor, and settled position evidence. Resume requires the same paused cursor and observes AUTO before reporting active. The original start deadline bounds all running phases.
- Completion requires observed final arrival, the final item reached report, a completed cursor, and a settled position. Helm requires a fresh explicit acquire.
- Abort can leave continuously owned AUTO through a bounded stop command. The host binds each stop to its admission mode through final send. An observed pilot exit or lost session retires the old AUTO authority even if the FC later reports AUTO. A deliberate pause can restore the owned interval through a fresh explicit resume and post-send AUTO observation. After takeover, use a fresh explicit release from a supported native handback mode. Release clears the lease only after independent settled evidence. Losing the bridge can leave the FC executing its native mission.
- After process restart, the private marker blocks effects. A supported non-AUTO mode and fresh settled dwell allow explicit handback using the new session. A subsequent start needs new verified content.
- Native acceptance records independent MAVLink and onboard evidence of motion, pause and stopped dwell, retained cursor, completion, takeover, abort, and restart handback for both models. Profile selection and source pins bound the evidence to these configurations.

## Replay and profile scope

Run `tests/rover_mission/run_native.py` with the pinned ArduPilot tree, the stock MOOS-IvP tree, the matching configured MAVMOOS build and a fresh output path. Select `--profile ground` or `--profile boat`. The harness takes the shared native host lock, uses an independent read-only MAVLink socket, and retains exact process, source and binary identity. The software test `ardu_rover_mission_runtime` loads the actual Rover control and mission modules.

The pinned Rover frame inventory uses the same mission commands and cursor protocol for conventional steering, skid steering, omni and vectored drives, balancebots, powered boats and sailboats. The bounded waypoint parser and protocol logic can be shared. Stop and Loiter evidence depend on the drivetrain or hull. Qualify `rover-skid` and `motorboat` separately before extending the tested profile claim. Balance, lateral drive and wind-dependent steering also need frame-specific motion and handback cases. [Pinned SITL frame inventory](https://github.com/ArduPilot/ardupilot/blob/04cf6486e8d42ce138de816e8466244346ed77cb/Tools/autotest/pysim/vehicleinfo.py#L422-L483)

## Run the workflow

For the selected owned SITL profile, configure `plugins=telemetry,ardurover_control,missions`, `control_native_actions=true`, `control_mission_execution=true`, and an absolute private `auto_recovery_directory`. Keep that directory across restarts. Configure a separate private [native replay directory](ardurover_control.md#native-replay-directory) for ordinary native requests such as arming. Use the normal stock-helm configuration when Guided helm will be used after handback.

1. Check `MAVMOOS_MISSION_EXECUTION_STATUS` for `upload_ready=true`. Upload while disarmed with `MAVMOOS_MISSION_REQUEST` and `id=plan1,action=upload,timeout=30,items=...`. Each item has the fields `seq:command:frame:current:autocontinue:param1:param2:param3:param4:x:y:z`. Separate items with `|`. Use command 16 for each row. The HOME row uses frame 0 and the FC's current global altitude. Waypoints use frame 3, `z=0`, and WGS84 degrees scaled by `1e7`. Keep them within 60 m of HOME.
2. Read the `verification_id`, `content_id` and `revision` from `MAVMOOS_STORED_MISSION_PROOF`. Arm using the ordinary native `MAVMOOS_COMMAND` path and wait for `start_ready=true`.
3. Post `schema=1,id=run1,action=start,timeout=100,verification_id=plan1,content_id=<content>,proof_revision=<revision>` to `MAVMOOS_MISSION_CONTROL`. For pause, resume, abort or release, send a fresh request such as `schema=1,id=pause1,action=pause,target=run1,timeout=14` to the same variable. Use unique IDs per session. Start is bounded to 120 s. Other transitions accept up to 15 s and their internal command phases are separately bounded.
4. Read `MAVMOOS_MISSION_EXECUTION_RESULT`, `MAVMOOS_MISSION_EXECUTION_LEASE` and `MAVMOOS_MISSION_EXECUTION_PROGRESS`. Wait for explicit settled handback before acquiring helm. After a restart, confirm the FC has left AUTO, then use `MAVMOOS_AUTO_RECOVERY_REQUEST` with `schema=1,id=handback1,action=handback,session=<new-session>`. Obtain the new session from `MAVMOOS_AUTO_RECOVERY_STATUS`.

The initial profile checks named readbacks for `MIS_RESTART=0`, ground `MIS_DONE_BEHAVE=0` or boat `MIS_DONE_BEHAVE=1`, `WP_SPEED` within 3 m/s ground or 2 m/s boat, `0 < WP_RADIUS <= 2` m, `AUTO_KICKSTART=0`, and `AUTO_TRIGGER_PIN=-1`. Stop evidence requires a fresh supported mode and at least five consecutive low-speed position samples spanning at least one second in both firmware and host time. Ground uses at most 0.25 m/s and 0.6 m excursion. Boat handback uses at most 0.45 m/s and 1.5 m excursion, allowing the bounded low-speed correction or drift recorded in SITL. A pause that races a terminal cursor leaves the lease for explicit handback when the same-cursor resume evidence cannot be established.
