# Air data observations

`air_data` is an optional startup-loaded observation module for an ArduPilot source with system and component IDs `1/1`. Select it in the existing `ProcessConfig = iMAVLink` block. The module can also run without `telemetry`. Its timing configuration takes seconds and is checked as one startup batch.

```text
plugins = telemetry,air_data
target_system = 1
target_component = 1
plugin.air_data.sample_timeout = 1
plugin.air_data.publish_interval = 0.1
```

The supported timeout range is 0.25 to 10 s, and the interval range is 0.02 to 2 s. The interval cannot exceed the timeout. The module observes existing inbound streams and registers no command or stream requests. The fixed-wing additions require an ArduPilot fixed-wing heartbeat on the selected route. For a receive-only fixed-wing fixture, use `expected_type = 1` and `expected_autopilot = 3`. The existing HUD, wind and pressure families retain their existing vehicle scope and payloads.

| MOOS publication | Wire family | Values |
| --- | --- | --- |
| `MAVMOOS_VFR_HUD` | `VFR_HUD` (74) | FC-reported airspeed, ground speed and climb in m/s, MSL altitude in metres, compass heading in degrees and throttle percent |
| `MAVMOOS_WIND` | ArduPilot `WIND` (168) | Raw direction-from bearing in degrees and the reported speed and vertical fields in m/s |
| `MAVMOOS_WIND_COV` | `WIND_COV` (231) | NED components, reported horizontal/vertical 1-STD variability and accuracy in m/s, MSL altitude in metres and a raw microsecond timestamp |
| `MAVMOOS_SCALED_PRESSURE` | `SCALED_PRESSURE` (29) | First reported absolute/differential pressure pair |
| `MAVMOOS_SCALED_PRESSURE2` | `SCALED_PRESSURE2` (137) | Second reported absolute/differential pressure pair |
| `MAVMOOS_SCALED_PRESSURE3` | `SCALED_PRESSURE3` (143) | Third reported absolute/differential pressure pair |
| `MAVMOOS_AIRSPEED` | `AIRSPEED` (295) | Fixed-wing sensor observations with separate receipt age for each ID, reported CAS, temperature, raw pressure and source flags |
| `MAVMOOS_HIGH_LATENCY_AIR_DATA` | `HIGH_LATENCY2` (235) | Fixed-wing FC-reported airspeed and setpoint, each with its raw byte and decoded m/s, plus the raw timestamp |

Each topic is a JSON schema 1 record. HUD, wind, scaled pressure and high latency each retain one sample with the wire family, message ID, original effective/read times, local age and source binding. `data` is null before a sample and after a session boundary. `AIRSPEED` carries a separate sample and metadata for each observed sensor. Republishing preserves observation IDs and original ages. A stale record keeps its last data with `fresh=false`. Expired heartbeat, reset or invalid owner time clears the cache. Queue-floor age is marked as an upper bound on age since local acquisition. The record leaves remote sample age and measurement quality unknown. `invalid_samples` counts rejected wire shapes and data for the corresponding family without replacing accepted observations.

`VFR_HUD` exposes `airspeed_reported_m_s` with `airspeed_basis=fc_reported_unspecified`. The pinned Copter sender can report a sensor reading, estimator vector magnitude or GPS groundspeed in that field. Its shared HUD sender can also retain a cached location. Local receipt age applies to the report. The module accepts finite speed, climb and altitude values, nonnegative speeds, compass heading from 0 to 360 and throttle up to 100 percent. [Copter 4.6.3 HUD source](https://github.com/ArduPilot/ardupilot/blob/92b0cd788ec29406f26c6f9c31d5ceedbd1cc538/ArduCopter/GCS_Mavlink.cpp#L225-L246) · [Shared HUD sender](https://github.com/ArduPilot/ardupilot/blob/92b0cd788ec29406f26c6f9c31d5ceedbd1cc538/libraries/GCS_MAVLink/GCS_Common.cpp#L3384-L3399) · [MAVLink VFR_HUD](https://mavlink.io/en/messages/common.html#VFR_HUD)

`WIND` preserves signed bearings such as the pinned Copter sender's `atan2` output. The schema describes the speed field as ground-plane speed, while that sender reports the full vector magnitude. The bridge accepts bearings in the signed or conventional ranges, keeps the speed and vertical fields as reported and leaves the choice of interpretation to a consumer with a sender-specific contract. [Copter 4.6.3 wind sender](https://github.com/ArduPilot/ardupilot/blob/92b0cd788ec29406f26c6f9c31d5ceedbd1cc538/ArduCopter/GCS_Mavlink.cpp#L1574-L1587) · [MAVLink WIND](https://mavlink.io/en/messages/ardupilotmega.html#WIND)

`WIND_COV` uses null for documented NaN component, variability and altitude values and for zero accuracy. Zero components remain valid values. The decoder rejects infinity, negative variability and negative or nonfinite accuracy. `time_usec_raw` is a decimal string so clients can retain the full unsigned wire timestamp. It does not contribute to local freshness. The two wind families remain separate reports. [MAVLink WIND_COV](https://mavlink.io/en/messages/common.html#WIND_COV)

## Fixed-wing airspeed sensors

`MAVMOOS_AIRSPEED` carries `family=AIRSPEED`, `message_id=295`, `read_only=true`, `authoritative_for_control=false` and `atomic=false`. The bounded `samples` array holds up to two independently acquired records for sensor IDs 0 and 1, matching the default count in the pinned ArduPilot source. `present` means the array contains a retained sample. Each item carries `sensor_id`, wire version, actual payload length, `metadata` and `data`. An update for one sensor leaves the other's age and value alone. The array clears on a source or session boundary and starts empty until the selected FC heartbeat binds. [Pinned airspeed sensor count](https://github.com/ArduPilot/ardupilot/blob/3fc7011a7d3dc047cbb17d8bd98ee94577d144c6/libraries/AP_Airspeed/AP_Airspeed_config.h#L59-L61)

`airspeed_reported_cas_m_s` carries the nonnegative finite reported speed under the MAVLink sensor field's CAS label. `temperature_cdeg` is null for `INT16_MAX` and retains signed centidegrees otherwise. The flags retain the complete `flags_raw` byte, the two bits `sensor_unhealthy_flag` and `sensor_used_flag`, and `unknown_flags_raw` for the remaining bits. These describe the received bits. No calibration or control inference follows from them. Legal MAVLink 2 tail truncation reconstructs zeros and preserves actual payload length. Infinity in pressure, nonfinite or negative speed, out-of-range sensor IDs and invalid framing reject the sample. [MAVLink AIRSPEED](https://mavlink.io/en/messages/common.html#AIRSPEED) · [Pinned generated message](https://github.com/mavlink/c_library_v2/blob/a2d0ecf011a4aaa7840480e43f4e38d8c9e79d29/common/mavlink_msg_airspeed.h)

`raw_pressure_wire` retains the signed numeric field and maps NaN to null. `raw_pressure_mavlink_unit=hPa` names the protocol's declared unit. The pinned ArduPilot 4.6.3 sender directly copies a getter documented in pascals, while its `SCALED_PRESSURE` sender multiplies the same getter by 0.01. The separate `differential_pressure_hpa_if_pinned_ardupilot_pa` is the wire value divided by 100 under that explicit sender assumption. For example, wire −175 becomes conditional −1.75 hPa. A consumer with an independently identified sender can select the correct interpretation. The fixed-wing heartbeat alone supplies no firmware version proof. [Pinned AIRSPEED sender](https://github.com/ArduPilot/ardupilot/blob/3fc7011a7d3dc047cbb17d8bd98ee94577d144c6/libraries/GCS_MAVLink/GCS_Common.cpp#L2398-L2407) · [Pinned pressure getter](https://github.com/ArduPilot/ardupilot/blob/3fc7011a7d3dc047cbb17d8bd98ee94577d144c6/libraries/AP_Airspeed/AP_Airspeed.cpp#L908-L914) · [Scaled pressure conversion](https://github.com/ArduPilot/ardupilot/blob/3fc7011a7d3dc047cbb17d8bd98ee94577d144c6/libraries/GCS_MAVLink/GCS_Common.cpp#L2317-L2331)

## Fixed-wing high latency air data

`MAVMOOS_HIGH_LATENCY_AIR_DATA` requires embedded fixed-wing type and ArduPilot autopilot fields consistent with the selected heartbeat. It retains `timestamp_ms_raw`, `type_raw`, `autopilot_raw`, `airspeed_raw` and `airspeed_setpoint_raw`. `airspeed_reported_m_s` and `airspeed_setpoint_reported_m_s` each decode the unsigned wire value at 0.2 m/s per step. The pinned shared sender takes the airspeed from its HUD function, which can fall back to an estimate or zero, and the Plane override supplies its controller's airspeed target. Both availability fields remain `unknown` and the reported speed basis is unspecified. Wire zero and 255 are preserved. Neither the message timestamp nor this family updates HUD freshness. ## Scaled pressure

The numbered pressure reports are independent. The pinned ArduPilot sender converts pascals to hectopascals and fills zeroes when either the barometer or airspeed half of the numbered pair is absent. `press_abs_hpa` is null when absolute pressure is zero. The signed absolute `temperature_cdeg` is null when both absolute pressure and temperature are zero. A nonzero temperature remains available when absolute pressure is zero. An absolute temperature of zero with positive absolute pressure remains zero. `press_diff_hpa` retains the signed reported value. Its `press_diff_availability` is `zero_ambiguous` for zero because the wire cannot distinguish missing data from a zero differential, and `nonzero_reported` otherwise. Negative absolute pressure and nonfinite pressure fields reject the sample. [Copter 4.6.3 sender](https://github.com/ArduPilot/ardupilot/blob/92b0cd788ec29406f26c6f9c31d5ceedbd1cc538/libraries/GCS_MAVLink/GCS_Common.cpp#L2299-L2361)

`temperature_press_diff_cdeg_raw` is null for an omitted extension or wire zero, with `temperature_press_diff_encoding=unknown`. Wire value 1 is preserved with encoding `zero_or_one_cdeg` because the sender also uses 1 to represent zero degrees Celsius. Other reported values retain their signed centidegrees with encoding `centidegrees`. `time_boot_ms` retains the unsigned wire stamp. Local freshness uses the original receipt metadata.
