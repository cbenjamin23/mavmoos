# ArduPlane control

Select `vehicle_profile=arduplane` with the `arduplane_control` startup provider. It groups stock-helm guidance, native modes, bounded Guided actions and verified runway execution behind one vehicle-control owner. The conventional `plane` model runs in owned local SITL. The FC owns flight stabilization, throttle and airspeed. The baseline flight starts in qualified native Loiter. The lifecycle fixture additionally starts from a disarmed runway and exercises takeoff and landing through `iMAVLink`. [Firmware fixture](../../config/firmware/arduplane-4.6.3-plane.json) · [Native mission](../../missions/plane_sitl/README.md)

| Start helm navigation | `MAVMOOS_NAV_CONTROL=acquire` | From qualified airborne Loiter, ask for Guided 15 once. Wait for a new heartbeat confirming Guided and a fresh stock helm decision after the grant. |

| Select native Loiter | `MAVMOOS_COMMAND=id=unique,action=loiter` | Relinquish an owned Guided grant or switch from qualified airborne RTL. The FC flies its own orbit. |

| Ground Manual | `MAVMOOS_COMMAND=id=unique,action=manual` | Recover from disarmed and stationary RTL or Loiter on the runway. |
| Arm or disarm | `MAVMOOS_COMMAND=id=unique,action=arm` or `action=disarm` | Send a non-forced command in stationary ground Manual. Arming requires selected FC prearm health. |
| Direct waypoint | `MAVMOOS_CONTROL_REQUEST=schema=1,id=unique,action=goto,strategy=guided,lat=…,lon=…,height=…` | Acquire from qualified Loiter, measure arrival in the admitted envelope and restore native Loiter. |
| Guided orbit | `MAVMOOS_CONTROL_REQUEST=schema=1,id=unique,action=hold,strategy=guided` | Fly a verified orbit at the current position and height. Optional `lat,lon` and `height` choose the center. |

| Relative altitude | `MAVMOOS_CONTROL_REQUEST=schema=1,id=unique,action=adjust_altitude,strategy=guided,delta=12` | From idle native Loiter, orbit the initial position while tracking the offset height above home. Complete on observed altitude change and restore Loiter. |

| Adjust airspeed | `MAVMOOS_COMMAND=id=unique,action=change_speed,delta=-4` or `action=reset_speed_min` | Remain in owned Guided. Send a bounded airspeed command and wait for a matching protocol receipt and measured airspeed. |
| Runway takeoff or landing | `MAVMOOS_MISSION_CONTROL=schema=1,id=unique,action=takeoff,verification_id=…,revision=…,content_id=…` or `action=land` | Execute the bound stored plan. Finish in airborne Loiter after takeoff or disarmed Manual after landing. |
| Release uncertain execution | `MAVMOOS_MISSION_CONTROL=schema=1,id=unique,action=release,target=operation_id` | Resolve a locally retained lease only after fresh safe native handback evidence. |

`MAVMOOS_COMMAND_RESULT` separates queue admission, local send and fresh FC mode. A mode observation confirms the reported FC state. The native qualification observes actual movement independently. Use a new command ID for each operation. Native mode requests require a fresh, qualified autonomous state. A request already in the intended native mode returns `NO_OP`. The normal return and Loiter transitions leave pilot-controlled modes alone. Guided airspeed adjustment uses 15–28 m/s, with a maximum 8 m/s change per request. The 15 m/s operator floor is the bridge profile limit. The FC independently retains its verified lower tuning limit.

Relative course accepts a signed 10–90° offset from the selected aircraft's current ground track and projects one point 300 m ahead. Relative altitude accepts a signed 5–25 m offset from the current home-relative height. The target must fit the ordinary Plane envelope. Both require idle native Loiter and establish a new bounded Guided operation, with an optional original timeout of 10–120 seconds. Arrival or the measured altitude change hands control back to native Loiter. An overlapping direct or stock-helm owner rejects the request. This interface adapts pArduBridge's `CHANGE_COURSE` and `CHANGE_ALTITUDE` to finite operations and the established point-target path. The native witness measures movement and altitude, while software tests fence a target encoded just before pilot takeover. ## Stock helm input

- `DESIRED_HEADING` is a ground course in degrees clockwise from true north.
- `DESIRED_SPEED` selects the 22 m/s ground-speed intent for this profile, with a 0.05 m/s input tolerance. The FC separately uses its verified 22 m/s cruise airspeed and TECS. Actual groundspeed and sensor airspeed are separate observations.
- `DESIRED_ALTITUDE` is 45–120 m above the bound FC home. The observed aircraft must remain within the provider's 35–160 m height envelope.
- The ordinary helm state must be fresh `DRIVE` with `IVPHELM_ALLSTOP=clear`. The shared adapter binds the source and groups the three scalars by their original publication ages, publication span and acquisition boundary. The `ARRIVAL_GROUPED` label describes that evidence.

MAVMOOS places a point 300 m along the ground course. Its admission disk is 1,200 m around home, with a 120 m allowance for orbit and turns. The point and aircraft must both be inside that allowance. The host sends standard `MAV_CMD_DO_REPOSITION` 192 in `COMMAND_INT` with integer lat/lon, home-relative altitude and the mode-change flag clear. It holds one newest pending input and waits for matching FC target readback before another point can be sent. Updates are at least one second apart. Less than 20 m of geographic change and less than 2 m of height change can reuse a recently confirmed point. The geographic bounds govern admission. Native orbit and return are measured separately. ## Stock helm tasks

Set `operation_helm_enabled=true` and `operation_helm_tasks=return,survey,voronoi` to expose the corresponding task requests. A mission can also configure `waypoint`. These operations select a configured stock behavior. The mission owns its waypoint, survey or partition geometry.

1. Start in qualified native Loiter with no other operation holding control.
2. Post `MAVMOOS_CONTROL_REQUEST=schema=1,id=unique,action=return,strategy=helm,timeout=55`. The selector publishes `MAVMOOS_HELM_OPERATION=return` and `MAVMOOS_OPERATION_RETURN_UPDATE=points=x,y` for the projected home route. Survey and Voronoi publish their own selector values for mission-defined routes.
3. Bind the behavior condition to `MAVMOOS_HELM_OPERATION` and configure `activeflag = MAVMOOS_HELM_TASK_READY=return` for the return behavior. Each other configured behavior uses its own action in the flag. `MAVMOOS_PLANE_HELM_TASK_STATUS` reports `acquire_ready=true` after a fresh exact flag from the configured `helm_source`.
4. Send a separate `MAVMOOS_NAV_CONTROL=acquire` while the flag is fresh. The original publication must follow the selector and be within two seconds at acquisition. The operation must still have the full native Guided acquisition window available. An early or stale acquire does not become a pending request. After acquisition, the ordinary adapter requires fresh `DRIVE`, clear all-stop and the complete stock scalar group.
5. Cancel with `MAVMOOS_CONTROL_REQUEST=schema=1,id=unique,action=cancel,target=task_id` or release navigation. Original timeout, changed home/observations or external mode takeover also retires the task. The bounded normal all-stop pause remains available within the task's original deadline.

The active flag is a stock behavior-transition observation. It confirms that the configured behavior produced an active objective after selection. The adapter separately checks the later scalar group and the bridge's target readback. The task duration bounds the initial permission, target and paused handoff. Configured task selection excludes direct Guided acquisition until the task retires. ## Verified runway execution

Enable `control_mission_execution=true`, load `missions` and configure an owned `auto_recovery_directory` to use the runway commands. The input plan has six rows in order. They are home, `NAV_TAKEOFF`, `NAV_LOITER_UNLIM`, approach entry, final approach and `NAV_LAND`. The two approach rows are regular `NAV_WAYPOINT` commands at matching heights. They must provide 160–360 m of aligned approach before the final landing glide. The bridge checks geometry before upload and compares the complete stored plan after readback. Copy the verification ID, revision and content ID from `MAVMOOS_STORED_MISSION_PROOF` into the command. Upload is limited to disarmed, grounded Manual.

Takeoff selects mission item 1, observes the new FC cursor and then requests AUTO. The bridge confirms climb and progression to the hold item before handing back to Loiter. On 4.6.3, landing selects item 3 and observes the same independent cursor boundary before AUTO. The aircraft flies the verified entry and final approach to touchdown. This path retains `RTL_AUTOLAND=0`. The firmware rejects arming with a stored `DO_LAND_START` marker and that RTL setting. `MIS_RESTART=0` is verified for both cursor-based workflows. [Pinned pre-arm policy](https://github.com/ArduPilot/ardupilot/blob/3fc7011a7d3dc047cbb17d8bd98ee94577d144c6/ArduPlane/AP_Arming.cpp#L436-L449)

The 4.7.2 profile explicitly enables `plane_native_autoland=true` with runway execution enabled. It verifies the selected firmware release and revision, its arming and watchdog settings, and the native approach configuration. The bound runway must agree with the grounded arming heading. A landing request uses native AUTOLAND 26. The FC computes and flies its own base and final approach. The 4.6.3 AUTO landing and 4.7.2 AUTOLAND remain separate firmware cells. [Plane 4.7.2 fixture](../../config/firmware/arduplane-4.7.2-plane.json) · [Native AUTOLAND](https://ardupilot.org/plane/docs/mode_autoland.html)

A landing mode confirmation means the FC entered its approach. Completion requires fresh grounded motion evidence, a disarmed heartbeat and observed Manual after the handback. The authority marker persists if link loss, a wrong cursor, expiry or an unexpected mode prevents a confirmed handback. Mode and motion evidence are independent of command ACKs.

## Handback and loss

`MAVMOOS_PLANE_STATUS` exposes conventional airborne readiness, the measured active sensor airspeed and its original age. `MAVMOOS_RUNTIME_STATUS` reports the typed profile parameter checks, watched heartbeat gate, fresh Guided confirmation, target readback and native handback. Use both statuses before sending an acquire.

A brief `NothingToDo` or `NoGoalBehavior` can pause a live grant while the last independently verified, bounded target remains current. A complete fresh decision can resume inside the configured handoff window if the FC stays Guided. Producer silence, invalid input, target change or a longer handoff fences navigation. With a fresh armed Guided heartbeat, the host attempts one bounded Loiter handback. Loss of the direct FC link, failure to confirm a handback, or a bridge restart in retained Guided withholds the watched heartbeat. The independently configured FC owns the resulting RTL. A restart waits for new native Loiter or RTL evidence and a new profile check before restoring the watchdog. Helm acquisition still starts explicitly from Loiter.

Pilot mode selection revokes the grant as soon as current FC mode is observed. The watched heartbeat continues across a healthy takeover. At this firmware pin, the watchdog can later enter RTL in FBWA if the actual link is lost. The direct fixture scopes the residual packet check to delivery outside Guided. A delayed UDP datagram already accepted by the OS carries neither an authority epoch nor an expiry on the wire. [Control coverage](../development/control-coverage.md)
