# Conventional ArduPlane operator parity

The scoped flight is one owned conventional ArduPlane SITL vehicle. A consumer starts the bridge while disarmed, uploads and reads back the named bounded mission, explicitly arms, takes off into a safe native orbit, flies through stock helm and direct Guided control, changes the commanded airspeed, returns, and lands and disarms. Use the existing native Loiter, RTL, watchdog and takeover regression cells alongside the new flight. Pin source, binary, firmware, helm and parameters in each receipt. Preserve the original deadlines at handoff and require independent FC state and physical motion for completion.

| Workflow | Operator and adverse acceptance |
| --- | --- |
| Arm and disarm | Non-forced ground commands. A later selected heartbeat and fresh ground state establish the result. In-air, stale or mismatched ground state is rejected. |
| Mission takeoff | Bind the explicit request to the verified takeoff and landing plan. Set and confirm the takeoff item before start. Observe native AUTO, the climb, the takeoff item progression and an independently reported safe Loiter handback. A stale proof, unintended mode or expired original deadline fences progress. |
| Direct waypoint and orbit | From native Loiter, acquire Guided, verify its positional target and measure motion toward the goal or a bounded orbit. Separate the direct owner from stock helm. Reject invalid geometry, overlapping ownership and delayed requests. |
| Airspeed adjustment | Restrict addressed Guided speed requests to the tested airspeed envelope. Require a matching fresh ACK and subsequent sensor observations of the result. Reject an out-of-envelope adjustment, expiry or takeover. |
| Landing | Verify the explicit approach plan and use the pinned firmware's native execution. Observe approach, touchdown and disarm. Require observed non-AUTO ground state before releasing the lease. Preserve the existing recovery marker on uncertainty. |
| Native mode and helm | Preserve fresh stock course/speed/height, Loiter, RTL, watchdog behavior and takeover cancellation. Exercise direct to helm ownership handback in the consumer flight. |

The pArduBridge source at `e34a62e` delegates Plane takeoff to `MissionRaw::start_mission`, Guided coordinates to the FC, and AUTOLAND to a MAVSDK mode selection. It exposes ordinary arm/disarm, airspeed adjustments and two separate native and Guided hold choices. [Original Plane command path](https://github.com/cbenjamin23/moos-ivp-uav-base/blob/e34a62ef49c2be42215a69c351850cbd85881486/src/pArduBridge/UAV_Model.cpp)

ArduPlane 4.6.3 routes `MISSION_START` to AUTO, `DO_LAND_START` to a verified landing sequence and Guided speed change through a separate command from parameter writes. The newer Plane 4.7.2 release exposes AUTOLAND mode, with its own configuration and independent acceptance. The two firmware workflows need separate qualification.
