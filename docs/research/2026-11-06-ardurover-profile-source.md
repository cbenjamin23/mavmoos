# ArduRover ground and boat profile source trace

The pinned ArduRover firmware revision is `04cf6486e8d42ce138de816e8466244346ed77cb`. MAVMOOS uses the same Rover control plugin for the explicit `ardurover` and `ardurover_boat` profiles. This trace records what informed the profile rules. Simulation qualification is tracked separately.

## Jeremy's BlueBoat bridge

Jeremy's application takes `DESIRED_HEADING` and `DESIRED_SPEED`, retains each MOOS publication timestamp, gates setpoints on armed Guided state, and converts course and speed to north/east velocity in `SET_POSITION_TARGET_GLOBAL_INT`. Its zero-speed path uses the observed heading and a small minimum velocity. Its `ALLSTOP` and manual-override paths can request disarm and Hold, respectively. These details come from lines 112–127, 163–210 and 878–949 of the archived source. Reference analysis and snapshot.

MAVMOOS reuses the planar helm interface, per-message age checks, Guided gating, velocity encoding, and current-heading rule at zero. Stock pHelmIvP continues publishing ordinary MOOS scalars. Its scalars pass the shared freshness and lease rules before the Rover backend translates them. Each profile sets a positive speed ceiling of 3.0 m/s for ground or 2.0 m/s for boats. True zero requests zero horizontal velocity with observed heading as the explicit yaw target. Helm loss can send one fresh, eligible zero target in Guided. Deliberate operator transactions own disarm, Hold, native Loiter, and RTL.

## Pinned Rover behavior

- **Identity and model.** ArduRover derives `MAV_TYPE_GROUND_ROVER` (10) or `MAV_TYPE_SURFACE_BOAT` (11) from its frame class. Both profiles require ArduPilot (3) and the pinned local SITL system/component 1/1. Upstream's `motorboat-skid` model runs the same `ardurover` executable and layers the Rover, motorboat, and skid-steer parameter files. It models differential propulsion. [Heartbeat type](https://github.com/ArduPilot/ardupilot/blob/04cf6486e8d42ce138de816e8466244346ed77cb/Rover/GCS_MAVLink_Rover.cpp#L10-L16) · [Model definition](https://github.com/ArduPilot/ardupilot/blob/04cf6486e8d42ce138de816e8466244346ed77cb/Tools/autotest/pysim/vehicleinfo.py#L451-L460) · [Motorboat physics](https://github.com/ArduPilot/ardupilot/blob/04cf6486e8d42ce138de816e8466244346ed77cb/libraries/SITL/SIM_Sailboat.cpp#L275-L327).
- **Guided targets.** The global-target handler checks Guided, converts horizontal velocity magnitude to speed and vector direction to heading, and accepts explicit yaw alongside velocity. Its own configured speed limit can further cap bridge targets. A zero-velocity packet with explicit yaw still enters the HeadingAndSpeed submode and starts its setpoint timer. [Message handling](https://github.com/ArduPilot/ardupilot/blob/04cf6486e8d42ce138de816e8466244346ed77cb/Rover/GCS_MAVLink_Rover.cpp#L843-L949) · [Target timer](https://github.com/ArduPilot/ardupilot/blob/04cf6486e8d42ce138de816e8466244346ed77cb/Rover/mode_guided.cpp#L330-L345).
- **Setpoint loss.** The FC expires its last heading and speed target after three seconds. Ground Rover then stops. A boat attempts its internal Guided Loiter submode and stops if entry fails. The boat still reports top-level Guided (15). If the FC receives the bridge's zero target on loss, it restarts the firmware timer, so the boat can drift before its internal Loiter starts. [Guided timeout](https://github.com/ArduPilot/ardupilot/blob/04cf6486e8d42ce138de816e8466244346ed77cb/Rover/mode_guided.cpp#L52-L73) · [Internal Loiter entry](https://github.com/ArduPilot/ardupilot/blob/04cf6486e8d42ce138de816e8466244346ed77cb/Rover/mode_guided.cpp#L387-L394).
- **Native Hold and Loiter.** Hold is mode 4. Native Loiter is mode 5 and is offered by MAVMOOS only for the boat profile, with fresh armed horizontal evidence. The FC estimates a stopping point on entry. Its Loiter controller can command thrust and steering outside its radius and uses the firmware speed policy. The bridge's 2.0 m/s ceiling applies to bridge-generated course/speed targets. A later operator acquire can deliberately request Guided from native Loiter. Every motion frame still requires armed, fresh Guided state. [Mode numbers](https://github.com/ArduPilot/ardupilot/blob/04cf6486e8d42ce138de816e8466244346ed77cb/Rover/mode.h#L13-L29) · [Loiter controller](https://github.com/ArduPilot/ardupilot/blob/04cf6486e8d42ce138de816e8466244346ed77cb/Rover/mode_loiter.cpp#L3-L72) · [Rover Loiter documentation](https://ardupilot.org/rover/docs/loiter-mode.html).
- **Environmental fixture.** The pinned motorboat parameter file enables wind and waves and contains a standalone `SIM_TIDE_0.5` entry. Tests should specify the intended wind, wave, and current values explicitly. The actual tide parameters are `SIM_TIDE_SPEED` and `SIM_TIDE_DIR`. The pinned simulator adds tide velocity when soft-armed.
