# Command and transition coverage

This matrix covers the seven vehicle-control providers and their named simulator profiles. The [release matrix](../../scripts/release/matrix.json) selects representative native scenarios for the release gate. The [capability registry](../../config/capabilities/copter.json) identifies implemented interfaces and software tests. Supplemental results keep their own firmware, source and artifact identities. Handoff runs · QuadPlane receive loss · QuadPlane selective loss and restart · Copter and Rover confirmation loss · Command outcome review · Durable request rollout · Supplemental restart and transition faults · Autonomy missions · Remaining provider missions · Compound mode stress

**SITL** means a linked run exercised the listed effect, rejection or transition with the named firmware and frame. **Software** means a deterministic test exercised the relevant host behavior using controlled inputs or wire faults. **Gap** means the linked evidence does not establish that specific native outcome. The entries summarize representative witnesses. A pass for a command family does not establish every alias, argument combination, state ordering or firmware release.

For effectful requests, verify admission, packet handoff, FC response and independently observed vehicle state separately. After a timeout or takeover, inspect packets as well as the terminal result. A late packet already handed to the network can have an effect, and renewed observations alone must not restore a retired grant. [Test selection and reproducibility](control-qualification.md)

## Priorities for new native cases

1. Inject delayed replies into the full native Precision Loiter and managed Copter/PX4 mission workflows. The loaded-provider tests now cover the previously reproduced ambiguity. The current selective takeoff ACK-loss case passed on all three Copter frames. Command outcome review
2. Extend the seven provider missions to more encounter geometries and changing environmental conditions. In-flight route updates currently have independent physical readback on the Copter survey.
3. Extend the supplemental fault cases to vehicle-specific boundaries, including pilot interruption of an actual VTOL transition and estimator loss on Ackermann.
4. Repeat the highest-risk cases on alternate pinned firmware or frames when the vehicle behavior differs. Keep exact native receipts and reuse deterministic tests for malformed requests, duplicate replies and final-send races.

Each new case should isolate one failure boundary or intentionally combine transitions whose interaction is under test. Report the exact simulator, profile and case outcome separately from the release gate count.
