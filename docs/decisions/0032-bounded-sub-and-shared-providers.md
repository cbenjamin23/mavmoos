# 0032 — Vectored Sub control and the final shared v1 workflows

November 6, 2026. The [v1 tracker](../plugin-progress.md) retains 34 startup providers. Vehicle-specific control stays with the selected firmware provider. Shared observers and estimator input have their own providers. All validation uses owned SITL or generated loopback input.

The ArduSub profile uses one vectored frame from a pinned development revision. Stock pHelmIvP supplies course, speed and positive-down depth referenced to the FC's surface home. Acquire requires native Position Hold, fresh depth, estimator and pressure evidence, followed by observed Guided entry and new helm inputs. The shared host retires obsolete navigation. One position-only local-offset target captures the FC's current position during a bounded hold. The pinned firmware accepts that local target in Guided, so an earlier handed-off hold cannot update the native Depth Hold controller. Explicit handback requires observation of Position Hold. Loss of bridge heartbeats exercises the configured native Depth Hold action. [ArduSub operator guide](../plugins/ardusub_control.md)

ExternalNav is a separate typed estimator input from one named producer on the dedicated disarmed Copter bench. The host verifies origin time, frame, covariance, run lease and fresh grounded evidence. It retains one pending sample, paces from the actual handoff and uses the earliest original deadline at the socket. This path shares the host's protocol budget. Firmware estimator use is verified from independent position and DataFlash, separately from local send acceptance. Passive odometry retains its original observation contract. [ExternalNav operator guide](../plugins/external_navigation.md) · [MAVLink ODOMETRY](https://mavlink.io/en/messages/common.html#ODOMETRY)

Mode catalog, Remote ID and component metadata are observation-only. Mode catalog preserves reported coverage and distinguishes current mode from firmware intent. Remote ID binds one selected source and redacts raw identifiers and error text. Component metadata verifies a bounded General v1 document from a provisioned private mirror using the advertised URI and MAVLink CRC. The CRC checks document integrity against the selected declaration. The mirror workflow requires no file transfer or network retrieval.
