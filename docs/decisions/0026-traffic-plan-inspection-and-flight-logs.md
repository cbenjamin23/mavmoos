# 0026. Traffic, plan inspection and flight logs

November 6, 2026. Implemented for the [three service and observation workflows](../plans/2026-11-05-autonomous-build-queue/README.md#plugin-milestones). The app retains a single selected vehicle connection, one shared host and ordinary stock helm input.

The optional [traffic observer](../plugins/traffic.md) retains at most 32 ADS-B contacts per selected ArduPilot session. Each entry ages from its own local acquisition. The wire age is a separate field because a forwarding FC can repeat a stored report. The module exposes traffic as operator information and leaves control authority with the existing provider. [Pinned MAVROS ADS-B handler](https://github.com/mavlink/mavros/blob/2d3f4db1101c7950c8817a9d788f0d11106fb261/mavros_extras/src/plugins/adsb.cpp#L75-L139)

The existing [missions provider](../plugins/missions.md) owns all plan inspection. A versioned request binds one plan type and one original deadline. Replies must match the selected peer, recipient, plan type and active request phase. A complete snapshot is assembled from individual replies. Empty, unsupported and incomplete are separate outcomes. No inspection can establish or renew AUTO proof. A conflicting flight snapshot invalidates the existing proof. Fence and rally inspection are independent of flight-plan proof. Existing flight-plan upload and verified readback still own proof creation. [Pinned MAVROS shared mission protocol](https://github.com/mavlink/mavros/blob/2d3f4db1101c7950c8817a9d788f0d11106fb261/mavros/src/plugins/mission_protocol_base.cpp)

The [flight logs provider](../plugins/flight_logs.md) selects a closed simulator log by its catalog identity and releases a complete file in one configured owner-private directory. The host accepts typed list, data and END messages. Log work shares the fair protocol budget and requires fresh disarmed and on-ground evidence at the final owned-socket check. The host serializes the transfer against control admission, mission mutation and the streamed parameter bench. Cancellation stops further data work. A same-operation END may use the fixed cleanup interval after data expires. A lost connection or ground prerequisite retires the transfer. [Pinned MAVROS log transfer](https://github.com/mavlink/mavros/blob/2d3f4db1101c7950c8817a9d788f0d11106fb261/mavros_extras/src/plugins/log_transfer.cpp) · [Pinned ArduPilot log transfer](https://github.com/ArduPilot/ardupilot/blob/92b0cd788ec29406f26c6f9c31d5ceedbd1cc538/libraries/AP_Logger/AP_Logger_MAVLinkLogTransfer.cpp)

END is unacknowledged. A successful local handoff and a later valid catalog are observable. Remote logging resumption requires separate evidence. The protocol sends neither a transaction nonce nor a file digest. Catalog identity, bounded ranges, complete coverage, EOF and a local checksum are the completion criteria for the selected closed-log fixture. The native test independently compares the file bytes against the simulator original.

The new typed service and callback move the matching-build C++ plugin interface to development ABI 10. External modules rebuild against the current headers. Earlier evidence retains its original source and ABI. All effectful tests use owned loopback SITL.

The implementation ledger records the source freezes, selected software and native results, and archive readback.
