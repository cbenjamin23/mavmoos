# 0021 — Observer recovery, protocol faults and distance observations

November 4, 2026. Status: implemented and qualified in the archived software/native configurations under the user's explicitly authorized three-stream scope. Stock pHelmIvP is unchanged; effectful testing remains owned SITL only. This adds no hardware route, general parameter write, mission execution or range injection.

Align attitude/system-status explicit reset with RC and the new distance provider: reset time must be finite, nonnegative and at least the last reliable Services time. A reset cannot move the reliable acquisition boundary backwards. Keep numeric component clock faults distinct from a raw host-clock reset reason. The existing Runtime protects its retained time on later faults; add fail-closed qualification of the initial injected sample. Invalid initialization denies module loading/configuration/effects until a new Runtime instance, while valid and explicit checkpoint-driven fake hosts retain their existing behavior.

Add `distance_sensor` as an optional observation capability using the shared connection/session. Preserve bounded sensor IDs, raw centimetres and converted metres, orientation/type, limits, quality/covariance/extension unknowns and original local ages. ArduPilot's message send time is not certified measurement generation time; zero covariance is unknown/invalid for this profile. No NAV projection, terrain-height substitution, readiness gate or control ownership follows from the measurement. Development ABI7 and default selection stay unchanged.

Expand protocol evidence with actual Runtime/modules, generated wire/CRC checks and dropped/duplicated/reordered/late receipt cases. A native service bench uses the production endpoint proof and drops selected validated receipts before Runtime dispatch; it does not claim to simulate network delay. Missing wind-write readback and mission final ACK retain possible remote effects, require explicit fresh-ID verification/restore/clear and cannot imply rollback. Untagged correctly addressed old replies remain an explicit correlation limit.

The new rangefinder flight uses an ordinary configured ConstantAltitude behavior's existing `ALTITUDE_UPDATE` interface, with targets5/8/5m above home. Sensor distance stays a separate observation. Independent native FC/DataFlash comparisons use late advancing data, explicit same-FC boot-time/value tolerances and separate probe/observer clocks; they establish no physical accuracy or general timing bound.

Primary source studies, old-code counterexamples, independent checker findings, exact source/artifact identities, measured results and remaining limits belong in the batch ledger. This record does not promote the project to hardware readiness, full MAVROS parity or a frozen public ABI.
