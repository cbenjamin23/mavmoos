# 0013: Concurrent features and explicit-command authority

Date: November 3, 2026. Status: accepted continuation scope; the detailed host policies are engineering choices under the user's instruction to keep going. Default receive-only, unchanged stock pHelmIvP and simulation-only effects remain mandatory.

## Trigger and reproduced behavior

The next increment tests parameter transfers while stock-helm navigation is active. Independent real-plugin/fake-I/O review found that normal handoff recovery and explicit commands did not share a sufficient host authority boundary. During a brief normal pause, fresh clear/scalars followed by HOLD, LAND or RTL could produce a `COMMAND_LONG` 76 and then NAV 84 in the same tick, with navigation permission restored. All three schedules reproduced at immutable `dba1611`.

Two additional schedules emitted an obsolete conditional position-hold 86 followed by fresh NAV 84 after a normal resume or explicit reacquire. That hold differs from the native Loiter HOLD mode command. An additional captured pre-interlock sequence emitted ARM 76 followed by parameter SET 23 while the latest observed state was still disarmed. These are software reproductions, not physical vehicle incidents. Independent review preserves source/artifact provenance and baseline/fixed outputs.

## Host policies

1. **Explicit acquisition and normal resumption are different services.** `acquireNavigation(id)` is a fresh explicit request. `suspendNavigation(resume_until)` may issue a normal-handoff permit only while a navigation grant is held, with a finite future deadline at most two seconds away, matching the maximum configurable helm handoff. A repeated suspension cannot renew the permit after the grant is suspended. `resumeNavigation(id)` requires that still-valid permit and current host eligibility.
2. **Every other revocation invalidates normal resumption.** An admitted explicit control command revokes navigation, cancels waiting NAV and internal acquisition-mode requests, invalidates the resume permit and clears waiting conditional-hold work. This includes an explicit Guided request even when Guided is already observed. A rejected malformed/ineligible request does not revoke authority.
3. **Control transactions temporarily interlock acquisition.** The host tracks at most four external command operations under original deadlines. Acquire/resume is denied while any is pending. `CommandRequest.operation_expires` carries the feature's operation deadline; zero uses the original send deadline. Bounds are validated before admission/authority changes. `commandFinished(id)` or original-deadline expiry releases the gate and cancels any still-waiting matching external command; neither restores NAV or recreates a permit. Commands already accepted by the OS cannot be recalled.
4. **Internal acquisition commands have private origin metadata.** An internally generated Guided request is distinguished in the queue, rather than inferred from a caller-controlled `acquire-` ID prefix. It cannot survive revocation of its acquisition. Routine telemetry-rate/heartbeat output is not an explicit operator transaction.
5. **A successful acquire/resume cancels obsolete conditional holds.** New authority must not emit an earlier waiting global-position hold immediately before a new navigation target. Already emitted work remains a separate residual concern.
6. **Parameter reads remain independent; writes respect known transitions.** Named reads and default paced inventory do not need NAV permission, an airborne vehicle, or an empty command gate. Explicit legacy wire-list streaming has the separate ground-bench composition policy in [0014](0014-paced-parameter-inventory.md). The existing restricted simulator write additionally requires no pending explicit control operation, at admission and final send. This prevents our own admitted ARM from being followed by a waiting SET based on still-old disarmed telemetry. It is not an atomic FC-state guarantee and cannot undo a write already sent before the transition.
7. **Rebuild matching development plugins at ABI 4.** The typed suspension/resumption, operation-deadline and terminal-notification contracts change the C++ development interface. No stable external ABI or untrusted-plugin isolation is promised. Current supported external commands are vehicle-control operations; future camera/other commands need their own policy classification rather than blindly inheriting NAV revocation.
8. **Suspended permits retain motion continuity at the host.** Before new ingress, after each applied vehicle observation and at resume entry, a suspended effectful grant requires fresh Guided/armed/in-air motion prerequisites. A mode takeover, pose lapse, disarm or landed transition invalidates it even if eligible observations return inside the original window. Suspension cannot create a permit while explicit Loiter-to-Guided acquisition is still pending. This is separate from that explicit acquisition grace, which remains supported. Shadow grants remain logical and produce zero effects.

## Example

A waypoint finishes and loiter starts within 0.5 s: the helm may resume using its bounded host permit and new fields. If the operator requests LAND during that gap, the permit is invalidated and the landing transaction interlocks navigation acquisition. A later clear event cannot reclaim permission. Completion, failure or timeout releases the busy gate, but returning to helm still needs a fresh explicit acquire and current eligible vehicle state.

## Concurrency acceptance

The bulk RX128/AppTick50 scenario requires a complete indexed parameter snapshot while NAV remains active and independent FC telemetry demonstrates airborne horizontal motion during the transfer window. The mission RX32/AppTick30 case characterizes bounded completion, incomplete transfer or audited heartbeat-session cancellation and any latched navigation loss; it does not promise transfer performance at those settings. A deliberate bridge pause must occur while the list is demonstrably pending, preserve original protocol deadlines, inhibit automatic NAV recovery and finish with explicit recovery/land/disarm. All in-flight SET probes must be rejected before parameter transmission and independently leave simulator wind unchanged.

Deterministic scheduling tests compare actual captured NAV send-time vectors with and without full-table/missing-index traffic. These establish fake-clock scheduling behavior, not an operating-system deadline. Native observations and Linux results are recorded separately in the batch ledger.

## Architectural implications and limits

The host owns shared authority and final effect eligibility; features own protocol accounting and policy proposals. This preserves the MAVROS-inspired shared connection/context organization and the MOOS-specific normal-handoff exception without depending on plugin order. No UDP/MAVLink format or stock helm modification is involved.

Current profiles assume one helm navigation producer and globally unique admitted command IDs from the trusted command feature. Broader multi-producer arbitration, command correlation beyond what MAVLink supplies, radio/load qualification and hardware remain outside this increment. Timeout/terminal notification is not proof that a remote command did not execute, and a new explicit acquire does not recall previously accepted bytes.

A second review caught three bare-host permit gaps within the default 0.5-second window: Loiter takeover, RTL then Guided, and a pose lapse followed by fresh data. The real stock-helm adapter already latched all three; the shared host service did not. Paired baseline/fixed diagnostics distinguish that host-contract issue from a demonstrated stock-profile takeback. The host now enforces the invariant independently of feature order/caller discipline.
