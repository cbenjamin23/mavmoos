# 0030. Conventional Plane guidance and watchdog handback

November 6, 2026. Implemented for the pinned conventional Plane SITL profile. Native evidence is recorded by scenario in the qualification ledger.

Keep one `arduplane_control` provider for native Loiter, RTL and stock-helm guidance. The provider supplies fixed-wing identity, observation and mode semantics, including the calibrated airspeed sensor and bounded target geometry. Runtime owns the grant, original intent expiry, command transaction, target readback and final send. The host and provider keep development ABI 10. Copter and Rover remain separate control choices alongside the same shared protocols and passive modules. [Previous capability decision](0017-vehicle-providers-and-mission-data.md)

## Decisions

- **Use a geographic Guided point.** Plane's pinned handler treats `DO_REPOSITION` as a position and optional orbit radius. It ignores that command's speed argument. Use a 300 m lookahead with a 1,200 m home envelope, 120 m turn and orbit reserve, and the existing FC airspeed configuration. Require a 22 m/s stock helm intent to select this profile. A native command result and target readback have separate timing and meaning. [Pinned reposition handler](https://github.com/ArduPilot/ardupilot/blob/3fc7011a7d3dc047cbb17d8bd98ee94577d144c6/ArduPlane/GCS_Mavlink.cpp#L836-L888) · [Pinned target reporting](https://github.com/ArduPilot/ardupilot/blob/3fc7011a7d3dc047cbb17d8bd98ee94577d144c6/ArduPlane/GCS_Mavlink.cpp#L243-L274)
- **Bind active settings before enabling the monitored heartbeat.** The host reads 16 typed parameter values on the same owned route. They cover conventional mode, selected SITL airspeed sensor, cruise envelope, return height and radius, and watched GCS policy. The checks use actual read time for the named protocol reply and a separate conservative acquisition-age bound. Mode and target evidence use conservative post-handoff acquisition. An independent fixture verifies the active parameters and an empty mission and rally set before flight. [Typed firmware and fixture manifest](../../config/firmware/arduplane-4.6.3-plane.json)
- **Require new mode and producer evidence.** Initial acquisition begins in native Loiter. A post-handoff Guided heartbeat and complete fresh helm inputs allow a point. Retain one awaiting point for two seconds, and prove the reported lat/lon and AMSL height match the sent point. ACK alone cannot identify a repeated position command. Keep a replaceable latest input and the same last-socket ownership and expiry checks. [Stock helm constraint](0004-use-stock-moos-ivp.md) · [Local egress boundary](0018-observations-and-final-handoff.md)
- **Preserve flight at a normal short handoff.** Fence pending admissions while the FC tracks a still-verified point. Fresh, complete post-pause mail can resume within the same grant and live mode. On longer or abnormal loss, one stop-only Loiter request is allowed while armed Guided is still known. A stop-only request can relinquish navigation even when the observations required for moving control expired. The FC can refuse Loiter, so require a fresh heartbeat in the requested mode.
- **Use the firmware watchdog for unresolved loss.** The watched heartbeat comes from bridge system 245. The fixture sets `FS_GCS_ENABL=1`, `FS_LONG_ACTN=1` and a five-second timeout. The host stops that heartbeat on stale reachability or after three seconds of unconfirmed Guided handback. Reconnecting or restarting in retained Guided does not renew the watchdog. Healthy pilot takeover preserves the heartbeat and revokes all bridge navigation. A later loss may still trigger the global FC watchdog in a pilot mode. The pin also seeds the watchdog time during boot. A startup RTL row is separate from the loss test, which must tie a new mode reason to the last watched packet. [Pinned startup and timeout](https://github.com/ArduPilot/ardupilot/blob/3fc7011a7d3dc047cbb17d8bd98ee94577d144c6/ArduPlane/system.cpp) · [Pinned watchdog action](https://github.com/ArduPilot/ardupilot/blob/3fc7011a7d3dc047cbb17d8bd98ee94577d144c6/ArduPlane/events.cpp#L171-L215)

The independent operator completes takeoff as part of the fixture. General ground-speed tracking, firmware-owned takeoff and landing requests exposed by MAVMOOS, QuadPlane, arbitrary wind envelopes and field operation need separate policies and qualification. The captured mode and target witnesses establish local behavior on the owned direct route. A datagram delivered in a later Guided grant remains an open transport hazard because the standard command contains no grant ID.
