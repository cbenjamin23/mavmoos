# 0024 — Checked external plugin startup and complete observer reference

November 5, 2026. Implemented in the app 0.11 candidate with development ABI 9. Qualification is recorded separately in the authoring ledger.

Adopt the [checked startup-batch proposal](../design/2026-11-05-plugin-configuration/README.md). The `plugin.<module_id>.<key>` route targets the actual selected, loaded name, which must remain unchanged through configuration. The host validates canonical names, owners, duplicates, reserved policy keys and bounded text before invoking callbacks. Modules receive one complete local batch, including empty defaults. Accepted results carry no error fields. Local generic timing names such as `publish_interval` may coexist with independent flat host settings. Existing flat built-in options apply first and remain compatible.

Keep the configuration interface separate from command admission. Runtime suppresses every mutating Services entry during construction, configuration, final validation and discard; an attempted mutation rejects startup even if ignored. Read-only queries and MOOS diagnostics remain allowed. The app keeps the guard active through its final subscription lookup, then explicitly finishes startup before registering those cached subscriptions and enabling dispatch. Failed configuration invalidates the Runtime, destroys partial module objects and closes app I/O. A late/repeated checked request is rejected without changing an already operational configuration. Selected identity, capability/resource ownership and final host profile/bench/control conditions are rechecked before operational dispatch. Startup module C++ code is trusted and remains resident; no stable ABI, hot unloading or live configuration is offered.

Ship one complete observer reference: independent build and actual loader, validated settings/defaults, fail-on-effect Services fixture, normal/sanitizer and negative tests, actual receive-only MOOS demonstration with independently observed zero wire output, and reproducible evidence. The bundled providers remain ten; the example is opt-in. Command authoring, AUTO restart and emergency policy, physical transports and hosted deployment are separate scopes. Stock pHelmIvP remains unchanged.

See the [developer guide](../development/external-plugins.md), [example](../../examples/heartbeat_observer/README.md) and [runnable demonstration](../../missions/external_observer/README.md).
