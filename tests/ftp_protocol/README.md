# Read-only MAVLink FTP transaction checks

This component implements one directory listing followed by one selected file download from the fixed simulator fixture directory `mavmoos-ftp`. An operator can start a new listing after a terminal result. The application owns the operation admission, FC binding, UDP socket and final send gate. The component consumes typed, padded FTP replies from that gate and stages bytes in memory.

## Wire decisions

- Requests use the standard 12-byte FTP header and 239-byte data area with little-endian sequence and offset. FTP replies echo the originating opcode and use the next sequence. ArduPilot's worker caches its last reply by bridge sender, client session and sequence. A retry reuses the entire request payload. New requests use even sequence values, which avoid ArduPilot's integer-promotion edge when retrying request 65535. The sequence cursor survives operations and reset. [MAVLink FTP protocol](https://mavlink.io/en/services/ftp.html), [ArduPilot 4.6.3 request and reply worker](https://github.com/ArduPilot/ardupilot/blob/92b0cd788ec29406f26c6f9c31d5ceedbd1cc538/libraries/GCS_MAVLink/GCS_FTP.cpp#L70-L234)
- The same client session, 1, is used with the owned FC for both LIST and GET. LIST advances by wire records, including unexposed names and skip markers, through offset 127. ArduPilot adds a second NUL after directory records, which consumes bytes and leaves the record offset unchanged. Explicit EOF publishes the listing. GET accepts an exact, previously listed basename and checks that its reported size still matches the listing. The host fixture uses a private directory of regular files. [Pinned MAVROS FTP listing parser](https://github.com/mavlink/mavros/blob/2d3f4db1101c7950c8817a9d788f0d11106fb261/mavros/src/plugins/ftp.cpp#L607-L672), [ArduPilot 4.6.3 directory handler](https://github.com/ArduPilot/ardupilot/blob/92b0cd788ec29406f26c6f9c31d5ceedbd1cc538/libraries/GCS_MAVLink/GCS_FTP.cpp#L584-L713)
- OpenFileRO returns a 32-bit file size. ReadFile requests advance by the exact positive byte count accepted, with offset checked on every ACK. The final one-byte probe must return EOF at the announced size, including for an empty file. The pinned ArduPilot ReadFile NAK leaves its offset zero. The file becomes available only after a matching TerminateSession ACK before the original deadline. [Pinned MAVROS FTP open and read handlers](https://github.com/mavlink/mavros/blob/2d3f4db1101c7950c8817a9d788f0d11106fb261/mavros/src/plugins/ftp.cpp#L674-L749), [ArduPilot 4.6.3 open and read](https://github.com/ArduPilot/ardupilot/blob/92b0cd788ec29406f26c6f9c31d5ceedbd1cc538/libraries/GCS_MAVLink/GCS_FTP.cpp#L235-L331)
- The receiver checks exact source 1/1, target network 0, destination 245/191, session, reply sequence, echoed request opcode and offset. Every accepted reply follows a locally accepted send of that logical request. An actual read after dispatch can carry a conservative queue floor slightly before dispatch. The floor must be ordered with the read and no older than 250 ms. The host supplies the acquisition stamps and owns the live FC session check.
- A GET stages up to 65,536 bytes, with one logical request outstanding, at most three handoff attempts per request and an original operation lifetime of at most 60 seconds. Local drop and response timeout retries wait 120 ms and 500 ms respectively. The socket handoff lease is at most 250 ms. Failure, cancellation or expiry discards the private stage. When an Open handoff may have reached the FC, only TerminateSession for that session can proceed after the original cutoff, bounded by its own deadline within two seconds of the original deadline. An unconfirmed close reports uncertainty and imposes a 3.1-second local quiet period before another listing. The quiet period and another LIST leave the remote state uncertain. A generic Open failure can indicate a retained descriptor and prompts cleanup of the same session. [ArduPilot 4.6.3 session handling](https://github.com/ArduPilot/ardupilot/blob/92b0cd788ec29406f26c6f9c31d5ceedbd1cc538/libraries/GCS_MAVLink/GCS_FTP.cpp#L199-L290)

The wire encoder allows ListDirectory, OpenFileRO, ReadFile and TerminateSession. A filename is a single ASCII basename of at most 80 characters, and it must start with a letter or digit. The four allowed opcodes keep access within the owned fixture. Firmware filesystem behavior comes from the pinned target and fixture. A size check and EOF verify byte count while the fixture keeps the selected file stable during the read. [ArduPilot 4.6.3 filesystem dispatch](https://github.com/ArduPilot/ardupilot/blob/92b0cd788ec29406f26c6f9c31d5ceedbd1cc538/libraries/AP_Filesystem/AP_Filesystem.cpp#L61-L114)

## Focused check

From the repository root, with a configured C++17 compiler

```sh
c++ -std=c++17 -Wall -Wextra -Wpedantic -Wconversion -Werror \
  -I src/libmavmoos_ftp src/libmavmoos_ftp/FtpTransaction.cpp \
  tests/ftp_protocol/FtpTransactionTests.cpp -o /tmp/mavmoos-ftp-transaction-tests
/tmp/mavmoos-ftp-transaction-tests
```

The fake peer models cached replies after lost Open and Terminate replies. Checks cover sequence wrap, directory paging, exact short reads, zero bytes, zero and maximum file sizes, wrong senders and stale replies, delayed ACK before queued retry, malformed records, file size changes, early EOF, expiry and cancellation. It runs without a socket, filesystem service or flight controller. App routing and owned SITL results belong in their separate receipts.
