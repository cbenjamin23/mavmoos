# Stock helm PX4 Offboard witness

This single native scenario exercises the pinned Linux ARM64 PX4 SIH quad package, firmware revision `fca3df865af36124a28c9d607e850f111dbaaea9`. It uses the package's Onboard UDP route 14580 → 14540 for MAVMOOS and the separate receive-only GCS route 18570 → 14550 for independent FC observations. The fixture verifies package binary and startup-script hashes, loopback isolation, and ownership of the simulator sockets.

The mission templates use stock pHelmIvP, the existing `BHV_ConstantAltitude` behavior and an eastbound `BHV_Waypoint`. pAntler starts MOOSDB, iMAVLink, the helm and pLogger. The operator probe publishes deployment and navigation authority requests. It records the MOOS publisher identity for each helm scalar and captures raw GCS MAVLink frames. The fixture's local PX4 CLI sets and verifies the simulated loss policy and performs takeoff and landing. The bridge requests the estimator stream on the owned Onboard route through its shared observation service. The bridge and FC select modes during the measured Offboard acquisition and loss.

Pass criteria include stock helm course, speed and height, zero prestream before explicit acquire, accepted hold prestream before an independent Offboard heartbeat, eastbound displacement under helm guidance, authority retirement after silence from the exact owned helm process, and independent PX4 Hold. After resuming the helm process, fresh stock scalars alone must leave the bridge latched with no new setpoints. A new acquire during failsafe Hold with intended Offboard must also reject. The fixture then selects native Hold locally and independently observes both reported and intended Hold before a fresh operator acquire. A second pass through prestream and eastbound travel must succeed. The operator releases authority before the fixture lands and disarms, followed by scoped process and port cleanup.

Build target `px4_offboard_moos_probe` with the usual app and modules. Run from a Linux container with network mode `none`, a read-only root, dropped capabilities, no-new-privileges, and a private writable temporary directory. Mount the exact installed PX4 package read-only at `/opt/px4`, the stock build volume at `/work`, source read-only, and a dedicated writable evidence directory. Run `python3 -B tests/px4_offboard/run_px4_offboard.py --source-revision "$REVISION" --output /evidence/run`. The output directory must be new. If the frozen build lacks a fixture executable, compile it separately and supply its absolute path with `--probe` or `--nsplug`. The fixture records the binary hashes either way.

`result.json` records the outcome and input hashes. `moos-wire.jsonl` carries host-monotonic MOOS and independent GCS observations. `gcs.mavlink` retains raw receiver bytes. Generated mission files, CLI activity, simulator logs and scoped teardown are included. [PX4 Offboard behavior](https://docs.px4.io/main/en/flight_modes/offboard) · [PX4 loss parameters](https://docs.px4.io/main/en/advanced_config/parameter_reference#COM_OBL_RC_ACT)

The expanded native witness passed with production `666de9a` and fixture source `e5b424c`. Each acquisition counted 13 prestream targets. Independent eastbound travel measured 4.017 m and 4.015 m. After deliberate silence, the bridge retired authority in 0.884 s and the independent observer saw Hold at 2.260 s. The fixture separately observed Hold/Offboard and then Hold/Hold, verified the rejected and accepted acquisitions, and closed with landing, disarm and owned cleanup.
